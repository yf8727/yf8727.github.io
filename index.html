01

Likeshop 电商平台登录接口性能测试

课程实训 · 独立完成 · 2026.09

Performance
  • JMeter 5.6.3
  • Fiddler 抓包
  • MySQL 存储过程
  • Python / pymysql
  • Nginx 日志
  • 容量评估

需求分析与用例设计

用 Fiddler 抓包拆解登录接口 POST /api/account/login 的请求结构与返回字段（data.token 供后续接口鉴权），据此制定响应时间、TPS、成功率、资源利用率 四类指标，设计 10 个业务场景用例。

测试数据构造

用 MySQL 存储过程与 Python（pymysql）脚本批量构造 10 万条用户数据；逆向分析并复刻 LikeShop 加盐加密规则 md5("y"+salt+"x")+"2020"，解决「造出来的数据无法登录」。

脚本开发与执行

按「参数化 → 请求 → 提取 → 断言 → 监听」结构开发 JMeter 脚本，按 5 / 10 / 30 / 50 / 100 五档并发梯度执行（Ramp-Up 10 秒、循环 60 次，累计 11700 次请求），同步采集 CPU、内存与磁盘 IO。

瓶颈定位

判定系统在 30 并发后出现拐点；100 并发时 20 个 php-cgi 进程全部崩溃、Nginx 返回 502（no live upstreams），错误率升至 28.35%。结合日志与监控锁定三大根因：php-cgi 进程数不足、未启用 OPcache、MySQL 默认配置保守。

优化与验证

  • 50 并发 TPS 25.8 → 37.0（↑43.4%）
  • 响应时间 1701ms → 1126ms（↓33.8%）
  • 100 并发错误率 28.35% → 0

02

宿舍便民报修微信小程序

毕业设计 · 独立开发 + 系统测试 · 2026.07

系统测试
  • 微信云开发
  • 5 集合建模
  • 六状态流转
  • 订阅消息
  • 黑盒用例 TC-01~09
  • 权限校验

项目背景

针对高校宿舍纸质报修流程繁琐、维修进度无法追踪的痛点，用微信小程序云开发（Serverless）实现报修系统，免去服务器采购与运维成本。

数据库与服务端设计

设计 user、repair_type、repair_order、repair_worker、evaluation 五个集合及关联关系，定义工单六状态流转（待受理 → 已派单 → 维修中 → 待确认 → 已完成 → 已关闭）；编写 login、submitRepair、assignOrder 等云函数，基于 openid 识别学生 / 维修人员 / 管理员三类角色并控制操作权限。

功能实现

在线报修（类型选择、故障描述、图片上传云存储）、进度查询、催办、确认与评价；管理端工单审核 / 派单 / 改派 / 关闭、维修人员管理与聚合统计；接入微信订阅消息在关键节点推送进度。

系统测试

以黑盒方法设计 9 条功能测试用例（TC-01 ~ TC-09），覆盖登录授权、报修提交、必填校验、进度查询、催办、派单、状态流转、评价与数据统计，全部通过；状态跳转与权限边界按角色逐一核对，防止越权操作。
